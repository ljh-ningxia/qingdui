# 轻队 QingDui

面向大学生与小型团队（3–8 人）的轻量任务管理工具。按《轻队 QingDui PRD V1.0（正式版）》实现。

**一句话**：微信群负责说，轻队负责记住谁什么时候交。

---

## 怎么跑起来

需要 Node.js ≥ 22.5（内置 `node:sqlite`，不需要装任何依赖）。

### 方式一：双击（推荐）

双击 **`启动.bat`**，等 3 秒浏览器会自动打开 <http://127.0.0.1:3001>。

> **那个黑色命令行窗口不要关。** 关了服务就停了，网页也就打不开了。用完再关。
> 窗口里如果显示 `服务已停止`，说明服务掉了，重新双击一次即可。

### 方式二：命令行

```bash
node src/server/index.js 3001
```

同样要保持这个终端开着。

### 方式三：后台常驻（关掉终端也不停）

```bash
node daemon.js 3001
```

它会以脱离进程拉起服务，然后自己退出，日志写到 `server.log`。

> 如果你是在普通 Windows 桌面上跑，这个方式可以直接用。
> 如果在某些受限环境（比如被上层进程托管的终端）里跑，子进程可能被连带回收 —— 那就用方式一或方式二，保持窗口开着。

### 打不开怎么办

按顺序排查：

1. **先看黑窗口还在不在。** 窗口关了 = 服务停了，这是最常见的原因。
2. **看窗口里有没有报错。** 红字贴给我。
3. **端口被占**：换一个端口 `node src/server/index.js 3002`，然后访问 <http://127.0.0.1:3002>。
4. **确认真的在监听**：`netstat -ano | findstr 3001`，有 `LISTENING` 才对。

首次登录：输入任意 11 位手机号 → 点「获取验证码」→ 页面会直接显示验证码（本地开发模式）→ 点「直接填入」→ 登录。

> 手机号是加密存库的（AES-256-GCM + HMAC 盲索引），页面上显示为 `138****8000`。

## 两个必须说清楚的地方

**1. 短信是本地模拟的。** 本地开发模式下，验证码直接显示在登录页，不真发短信。频率控制、有效期、锁定逻辑与线上完全一致，只有「调用短信网关」这一步是桩。接真网关只需改 `src/server/api.js` 里 `sendSms()` 一处。

**2. H5 不能推送。** 这是 PRD 里就承认的结构性短板，所以提醒做了 4 层兜底：站内红点 → 每日汇总 → 逾期横条 → `.ics` 系统日历。最可靠的是最后一层，因为它不依赖用户打开网页。

## 配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `QD_PORT` | 3001 | 端口（也可 `node src/server/index.js 3111` 直接传） |
| `QD_DB` | `data/qingdui.db` | SQLite 路径，`:memory:` 为内存库 |
| `QD_SECRET` | **生产必须显式设置** | 会话与数据加密密钥，至少 32 字符 |
| `QD_DEV_CODE` | 关闭 | 设为 `1` 才在响应里回显验证码（仅限本地） |
| `QD_SCHEDULER` | 开启 | 设为 `0` 关闭后台提醒与清理调度 |

**关于 `QD_SECRET`（重要）**

- **生产环境**：`NODE_ENV=production` 时缺这个变量会直接**拒绝启动**，不会退回到任何默认值。
- **本地开发**：未设置时自动生成随机密钥并写入 `.qd-dev-secret`（已在 `.gitignore` 中排除），重启后仍然有效。
- 生成一个：`node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`

**关于 `QD_DEV_CODE`**

只有显式设为 `1` 才回显验证码，且生产环境强制忽略这个开关。默认关闭。本地开发想图省事就这样启动：

```bash
QD_DEV_CODE=1 node src/server/index.js
```

## 后台任务

服务启动时会拉起调度器（`src/server/scheduler.js`）：

- **提醒**：每分钟检查一次，内部按 `(user, task, offset, channel)` 幂等去重，所以不会重复打扰。覆盖每日 08:30 汇总、截止前 24h/2h 加急、逾期次日 09:00。
- **清理**：每小时检查一次，把解散超过 30 天的小组连同任务、附件、评论、动态一并硬删除。

服务启动 3 秒后会先补跑一轮，避免「08:30 那轮因为服务器还没启动而错过」。

| C4 | 解散后部分写接口仍可用 | 只读判定下沉到路由派发层，统一拦截 |
| C5 | 上传信客户端声明的 `size`，配额可绕过 | 按真实解码字节数判定与计费 |
| C6 | 提醒与 30 天清理从未被触发 | 新增 `scheduler.js`，服务启动即运行 |
| C7 | `transfer_to` 未校验，可把任务转给不存在的人 | 必须是本组在册成员 |

## 仓库可见性

本仓库为 **Private（私有）**，由发布脚本强制指定。

P0 问题已修复，理论上可以公开；但公开与否属于产品决策而非技术决策，当前保持私有。需要转公开时，在 GitHub 的 Settings → General → Danger Zone 里操作即可，不需要改代码。

需要给他人使用产品时，有两种方式，都不必公开源码：

1. 把工作目录打包成 zip 直接发给对方（`data/` 与 `.qd-dev-secret` 均已在 `.gitignore` 中排除，分发包里不含数据库和密钥）；
2. 在 GitHub 上另建一个只含发布产物的仓库。
